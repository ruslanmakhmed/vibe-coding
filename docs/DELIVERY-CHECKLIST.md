# Оставшиеся действия для сдачи

Этот репозиторий подготовлен в одной рабочей сессии. Ниже действия, которые должны быть выполнены на настоящих стендах и в удалённом Git-хостинге: заранее создать историю задним числом или написать вместо неё выдуманные результаты означало бы подменить доказательства.

- Создать приватный GitLab/GitHub remote, заполнить inventory настоящими узлами и заменить учебный SSH-ключ в Vault.
- Проверить изменения в отдельной feature-ветке, отправить минимум пять feature-веток через merge request с собственным review, оставить `main` для слияний.
- Фиксировать реальные контрольные точки и теги `v0.1.0`, `v0.2.0`, `v1.0.0` вместе с соответствующими Docker image tags. Не ставить эти теги на текущий незавершённый снимок.
- Запустить `scripts/bootstrap.sh`, проверить сохранность созданной ссылки после `down`/`up`, затем выполнить `healthcheck.sh` и `backup.sh`.
- Прогнать `ci/run-stage.sh lint`, `build`, `push`, `deploy` с установленными инструментами, реестром, Kubernetes credentials и защищёнными CI variables.
- На реальном Debian/Ubuntu узле проверить Ansible `--check`, первый прогон и второй прогон с `changed=0`.
- Развернуть k3d с Ingress, проверить persistent volume после удаления pod, выполнить выкатку и откат.
- Открыть Prometheus Targets и убедиться, что `shortlink` имеет `UP`; проверить Grafana dashboard и правило алерта.
- Выполнить два сценария из `docs/INCIDENT.md` и заполнить отчёты наблюдениями и отвергнутыми гипотезами во время инцидентов.
- Провести чистое развёртывание по README с секундомером и подготовить личное объяснение решений к защите.
